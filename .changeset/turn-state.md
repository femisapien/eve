Clearing a session's context now also withdraws its pending approvals, session-limit prompt, and sign-ins, so a later answer to one of them no longer runs the earlier tool call. eve now runs approved tool calls itself before the model reads their results, and answering some of a step's approvals returns the session to waiting, so `respond()` resolves instead of waiting for the rest. Sessions started on an earlier eve version cannot resume or hand off to this one; start a new session.

The stream now reports every request eve withdraws: cancelling a turn, clearing the context, or a task's run ending emits `input.resolved` with outcome `"cancelled"` (or `authorization.completed` with outcome `"failed"` for a sign-in) before the event that ends it, so clients stop showing those requests. A question or sign-in from a subagent task now names the turn of the call the task serves, so it appears in that turn's message instead of the first one, and cancelling the task withdraws it. A sign-in callback's `authorization.completed` now comes before the turn it resumes, and a tool call that stops to ask for a sign-in now settles as failed with `AUTHORIZATION_REQUIRED` instead of staying open. Channel activity now settles each call from the same stream facts, and reports a call that a failed turn cut off as `interrupted`. `eve dev` warns when a session's stream breaks these rules.
