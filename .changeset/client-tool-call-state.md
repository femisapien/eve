`toolCallState()` from `eve/client`, `eve/react`, `eve/vue`, and `eve/svelte` tells a UI whether a tool call is running, awaiting input, completed, failed, rejected, cancelled, or interrupted. It reads the same session projection eve folds for its own activity, so a UI and eve's channels agree on every call, and the facts it reads come from the stream: which turn runs an approved call, which calls a sign-in stopped, and which of this session's calls a subagent's passed-up approval waits on (`ConversationInput.callId`). Call it as `toolCallState(conversation, part)`, with `{ streaming: false }` once the stream stops; it no longer takes a `turnId`. `signInState()` reads where a sign-in part's attempt stands, and sign-in parts always carry their `attemptId`. Tool parts also keep the tool's authored `label.start` and `label.complete` copy as `toolMetadata.eve.label`, and a failed call's error code as `toolMetadata.eve.errorCode`; `eve dev` uses them to label a subagent's own tool calls and hide refused task calls.
